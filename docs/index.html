The wedge

One record. Two readers.

The English is the clinical note and the pharmacist's check. The Urdu is what the family takes home. Neither is translated from the other — each language has its own authored word order.

Urdu a person would write

Composed from slots, pluralised per language, with drug names and doses held upright inside right-to-left text. Not “1 tab BD” with the words swapped.

Same medicine, both registers Give 5 ml twice a day after food for 7 days 7 دن تک کھانے کے بعد دن میں دو بار 5 ملی لیٹر دیں

Preview is print

The on-screen sheet and the PDF come from the same layout engine and the same text shaper, at exact millimetre dimensions with fonts embedded. What you approve is what the printer receives.

  • Signature block pinned to the page bottom
  • A medicine and its Urdu never split across pages
  • Minimum Urdu point size enforced

The library suggests. You confirm.

Doses arrive with their citation attached and are never filled in silently. Growth percentiles are computed once, from WHO or CDC tables, and stored with the reference that produced them.

  • No dose without a source
  • No test suggested from a diagnosis
  • No machine translation, anywhere
Architecture

Where your data lives

Two layers, and only one can ever be shared. A receptionist cannot read clinical content because it is not on their machine — enforced by which data exists, not by a permission flag someone can be talked into changing.

Clinic layer

Shared, when a clinic has a front desk

Patients, today's queue, paid status, visit fee.

  • Lives on the clinic's own machine
  • Never on a server anyone else operates
Clinical layer

Always the doctor's own device

Prescriptions, examinations, growth records, learned vocabulary.

  • Never transmitted, to anywhere
  • A front-desk device refuses to store one
Solo practice is the simple case Both layers sit on one machine, nothing syncs, and the queue is switched off entirely — a doctor working alone never meets it.

Setup

One machine, or two

Working alone? Do the first two steps and stop.

Solo — one device

  1. Fill in your details

    Name, qualifications, registration number, clinic. Choose A4 or Letter, and whether you print on plain paper or a pre-printed pad.

  2. Set a backup passphrase, and export today

    Records live only on this device. The encrypted export is the only way back from a lost phone or a cleared browser. There is no reset, because there is nothing held anywhere to reset from.

Front desk + consulting room

  1. Run the station on the reception PC

    Copy nabz-clinic.exe and double-click it. Allow it through Windows Firewall on Private networks only. It prints its address and a six-digit pairing code.

  2. Reserve that PC’s IP on your router

    Not optional. Browser storage is tied to the address the app was opened from, so if the address moves, the doctor’s device opens an empty app.

  3. Tell each machine what it is for

    Asked once, on first run. A front desk shows only the queue and cannot save a prescription at all — not hidden, not permitted.

  4. Install the clinic certificate on the doctor’s device

    Open the station’s http:// address and follow it. On iPhone this is two steps and the second is easy to miss: install the profile, then Settings → General → About → Certificate Trust Settings.

  5. Open the https:// address and enter the pairing code

    Add it to the home screen. The queue then syncs both ways on its own, and keeps syncing while you are writing a script.

Why the certificate is not optional Over a plain http:// address a browser silently switches off encrypted backup, the PIN and offline use — on the one device holding every clinical record. The certificate is what turns those back on.
For developers

Run it from source

Node 20+. No database to provision, because there is no database.

npm install
npm run assets         # WHO/CDC growth tables + OFL fonts, from their publishers
npm run build
npm start              # serves the app only, stores nothing

npm run start:clinic   # reception station: also shares the queue on the LAN
npm run build:exe      # -> release/nabz-clinic.exe, one self-contained file
Assets are fetched, not committed The growth tables and the Nastaliq fonts come from WHO, CDC and Google Fonts at build time, so every value is traceable to its publisher rather than to a copy someone pasted into a repository years ago. Without them the growth module refuses to compute and the renderer refuses to draw — loudly, rather than producing a document with no Urdu in it.
