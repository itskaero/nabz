Prescriptions a parent can actually read.

Nabz writes the clinical record in English and the patient's instructions in proper Nastaʿlīq Urdu — composed from structured data, never machine-translated, and printed to hold up on a cheap mono laser.

Every record stays on the doctor's own device. There is no account, no cloud, and no server that holds a diagnosis.

What it produces

One structured record, rendered twice. The English is the clinical note and the pharmacist's check; the Urdu is what the family takes home. Neither is translated from the other — each language has its own authored word order.

The wedge

Urdu that reads like a person wrote it

Instructions are composed from slots, pluralised per language, with drug names and doses held upright inside right-to-left text. Not "1 tab BD" with the words swapped.

Preview equals print

One renderer, two outputs

The on-screen sheet and the PDF come from the same engine and the same shaper, so what you approve is what the printer receives.

Safety

The library suggests; you confirm

Doses arrive with a citation attached and are never filled in silently. Growth percentiles are computed once, from WHO or CDC tables, and stored with the reference that produced them.

Where your data lives

Two layers, and only one of them can ever be shared. A receptionist cannot read clinical content because it is not on their machine — enforced by which data exists, not by a permission flag.

LayerHoldsLives
Clinic Patients, today's queue, paid status, visit fee Shared, when a clinic runs two machines
Clinical Prescriptions, examinations, growth records, learned vocabulary Always the doctor's own device
Solo practice is the simple case. Both layers sit on one machine, nothing syncs, and the queue is switched off entirely — a doctor working alone never meets it.

Setting it up

One machine or two. If you are working alone, do step 1 and stop.

Solo — one device

  1. Open the app and fill in your details

    Name, qualifications, registration number and clinic. Choose A4 or Letter, and whether you print on plain paper or a pre-printed pad.

  2. Set a backup passphrase, and export today

    Records live only on this device. The encrypted export is the only way back from a lost phone or a cleared browser.

Two machines — front desk and consulting room

  1. Run the station on the reception PC

    Copy nabz-clinic.exe and double-click it. Allow it through Windows Firewall on Private networks. It prints its address and a six-digit pairing code.

  2. Reserve that PC's IP on your router

    Not optional. Browser storage is tied to the address the app was opened from — if the address changes, the doctor's device opens an empty app.

  3. Set each machine's role

    On first run each device asks what it is for. A front desk shows only the queue and cannot save a prescription at all.

  4. Install the clinic certificate on the doctor's device

    Open the station's http:// address and follow it. On iPhone this is two steps and the second is easy to miss: install the profile, then Settings → General → About → Certificate Trust Settings.

  5. Open the https:// address and enter the pairing code

    Add it to the home screen. The queue then syncs both ways on its own.

Why the certificate matters Over a plain http:// address a browser switches off encrypted backup, the PIN and offline use — silently. On the device holding every clinical record. The certificate is what turns those back on.

Running it from source

npm install
npm run assets      # WHO/CDC growth tables + the OFL fonts, from their publishers
npm run build
npm start           # serves the app only, stores nothing

npm run start:clinic   # reception station: also shares the queue on the LAN
npm run build:exe      # -> release/nabz-clinic.exe, one self-contained file

The growth tables and fonts are deliberately not committed — they are fetched from WHO, CDC and Google Fonts so every value is traceable to its publisher rather than to a copy someone pasted in years ago.
