Setting up the clinic station

From one file on a reception PC to a doctor's phone that can write, print and back up. Every step here exists because something goes wrong without it — the reasons are given, not just the instructions.

Which setup do I need?

Two shapes, and the smaller one is the common one. Nothing about the two-machine setup is required to use Nabz.

You haveWhat to do
One device
You see patients and write scripts yourself		 Open the app, fill in your details, set a backup passphrase. Two steps, and you are finished. The queue stays switched off and you never meet it.
Two machines
Someone at a front desk, you in a room		 Run the station on the reception PC and follow steps 1–6. Around fifteen minutes, once.

Solo — one device

  1. Open the app and fill in your details

    Settings → Your details. Name, qualifications, registration number and clinic. Choose A4 or Letter, and whether you print on plain paper or a pre-printed pad — if you use a pad, the app leaves your letterhead zone blank instead of printing over it.

  2. Set a backup passphrase and export today

    Settings → Your records live only on this device. Pick a passphrase of at least eight characters and press Export my data. Keep the file somewhere that is not this device.

There is no password reset The backup is encrypted with your passphrase and nothing about it is held anywhere else. If you forget it, the file cannot be opened — not by us, not by anyone. Write it down somewhere you would keep a bank card PIN.

1 · Run the station on the reception PC

The station is one file. The whole app is inside it — the HTML, the typesetting engine, the Nastaliq font — so there is nothing to install and no runtime to set up first.

  1. Copy nabz-clinic.exe onto the reception PC

    Somewhere it can stay, such as C:\Nabz\. It writes the queue into a folder beside itself, so keep it out of Downloads.

  2. Double-click it

    Windows will warn that the publisher is unknown: More info → Run anyway. That warning is accurate — the binary is not code-signed, which is listed under limitations.

  3. Leave the window open

    Closing it stops the station. Minimise it instead. Everything it needs to tell you is printed in that window.

On first run it prints something like this, and creates its own certificate:

  Nabz - clinic station
  ---------------------

  On this computer:      https://192.168.0.159:8443

  FIRST TIME on a phone or tablet, open this and follow it:
     http://192.168.0.159:8080
  It installs the clinic certificate. Without it the browser
  switches off backup, the PIN and offline use.

  Afterwards, open:      https://192.168.0.159:8443

  This machine holds the queue: names, ages, tokens, payment.
  It does NOT hold prescriptions, examinations or growth records
  - those stay on the doctor's own device.

  Pairing code for a new device:  203329
Write down that pairing code You need it once per device. It is kept in the station's data folder, so it survives restarts — you can always read it again from the window.

2 · Let it through the firewall

Windows asks the first time the station starts. Tick Private networks and leave Public networks unticked.

Private means "the network I trust", which is what a clinic's own wifi is. Public is the setting for an airport or a café, and it blocks the incoming connections the doctor's device needs to make.

If you missed the prompt, or clicked the wrong thing Windows Security → Firewall & network protection → Allow an app through firewall → find Node.js or nabz-clinic, and make sure Private is ticked.

Also check the network itself is marked private: Settings → Network & Internet → your connection → Private network. A clinic LAN classified as Public will keep blocking things no matter what else you do.

3 · Reserve the station's IP address

This step is not optional, and skipping it is the way this setup loses records.

A browser files what it stores under the address the page came from. https://192.168.0.159:8443 and https://192.168.0.42:8443 are, to a browser, two unrelated applications with two separate databases. If the router hands the station a different address next week, the doctor's device opens an empty app. Nothing is deleted — it is behind an address that no longer exists.

  1. Find the station's address and its MAC

    On the reception PC open Command Prompt and run ipconfig /all. Note the IPv4 Address and the Physical Address of the adapter that is actually connected.

  2. Open your router's admin page

    Usually http://192.168.0.1 or http://192.168.1.1. Look for DHCP Reservation, Address Reservation, or Static Lease.

  3. Pin that MAC to that IP, and save

    Then on the PC run ipconfig /release followed by ipconfig /renew. Confirm it comes back with the address you reserved. A reservation usually only takes effect at the next lease renewal, so without this the address can stay wrong for hours.

Reserve the right adapter A laptop has both wifi and Ethernet, each with its own MAC. Reserving the wifi address while the PC is plugged into Ethernet reserves nothing. Ignore any adapter named VirtualBox, VMware, Hyper-V or WSL — those are virtual and unreachable from other devices.

4 · Tell each machine what it is for

The first time the app opens on a fresh device it asks one question. The answer decides what that machine is allowed to hold.

Front desk

Shows the queue and nothing else. Prescriptions, examinations, growth records and history are not merely hidden — the app refuses to save a prescription on this device at all. That is what makes "the receptionist cannot read clinical records" a fact about the machine rather than a promise.

Doctor's device

Everything. This device holds the only copy of every clinical record, which is why the backup step matters more here than anywhere else.

You can change it later in Settings → What this computer is for. Switching a device that already holds records does not delete them; it tells you how many there are first, and switching back finds them intact.

Choosing Front desk also switches the queue on, since that is the only thing that machine does.

5 · Install the clinic certificate

Do this on every doctor device — phone, tablet or laptop. It takes two minutes and it is the difference between a working app and a crippled one.

Why it is necessary

Browsers switch off a set of capabilities on any address that is not secure. A plain http://192.168.… address is not secure, so on that address the browser silently removes:

  • Encrypted backup and restore — the only recovery path for records that exist on one device
  • The PIN lock
  • Offline use — the app stops working when the station is off

None of that announces itself. The app looks fine and quietly cannot back itself up. Nabz shows a banner when it detects this, but the fix is the certificate.

Clicking through a browser warning does not work A certificate the device does not trust fails exactly the same way plain http:// does. The device has to genuinely trust the issuer, which is what installing this does.

Install it

  1. Open the station's plain address

    The http://…:8080 one from the station window. That address now serves only a setup page — the app itself is on https://.

  2. Tap "Download certificate"

    Then follow the instructions for your device below.

iPhone / iPad

  1. Settings → Profile Downloaded → Install
  2. Settings → General → About → Certificate Trust Settings
  3. Switch on Nabz Clinic Station CA

Step 2 is separate from step 1 and is the one everybody misses. Without it nothing changes.

Android

  1. Settings → Security
  2. Encryption & credentials → Install a certificate
  3. Choose CA certificate, accept the warning, pick the downloaded file

Wording varies by manufacturer. Searching Settings for "certificate" usually finds it.

Windows / macOS

  1. Double-click the downloaded file
  2. Windows: Install Certificate → Local Machine → place in Trusted Root Certification Authorities
  3. macOS: add to the System keychain, then set it to Always Trust
What you are agreeing to, and how to undo it A certificate authority can vouch for any site to that device, so this is a real decision. This one was generated on the clinic's own computer and its private key never leaves it. To reverse it, remove Nabz Clinic Station CA from the same settings screen you installed it in.

If the station's address changes later, it reissues its certificate automatically and no device has to trust anything again — the authority stays the same, only the certificate under it is replaced.

6 · Pair the doctor's device

  1. Open the https://…:8443 address

    No certificate warning should appear. If one does, the certificate did not install — go back to step 5, and on iPhone check the Certificate Trust Settings half.

  2. Add it to the home screen

    Safari: Share → Add to Home Screen. Chrome: menu → Install app. It then opens like an app and keeps working when the station is off.

  3. Open the Queue tab and enter the pairing code

    Six digits, once. After that the queue syncs both ways on its own.

  4. Fill in your details and export a backup

    Same as the solo setup. This device holds the only copy of every record.

Daily use

Once set up, nobody touches any of the above again.

At the front deskIn the room
Type name, age, sex and fee → Add. The patient gets today's next token.

Mark paid, unpaid or waived as money changes hands.

Added by mistake? Remove works while the row is still waiting. 		The row appears within about ten seconds, without pressing anything.

Open script → confirm it is the right child → the row moves to in room and their details carry into the prescription.

Save closes the visit: the row goes to done and you are returned to the queue.

The day's figures sit at the top of the queue: waiting, seen, collected and outstanding. Collected and outstanding are kept apart deliberately — a single "revenue" number that quietly included money nobody has handed over is exactly the number that gets believed.

Syncing continues while you are writing a script, not only while the queue is on screen, and it catches up immediately whenever you switch back to the app.

Backups

The doctor's device holds the only copy of every clinical record. Nothing is on the station, nothing is on any server. A lost phone or a cleared browser is a lost record unless a backup exists.

  • Settings → set a passphrase → Export my data
  • The file is encrypted; keep it somewhere that is not the device itself
  • The app nags after seven days without one, deliberately and repeatedly
  • Restore with Restore a backup and the same passphrase

The station's own folder is worth copying to a USB stick occasionally too. It holds only the queue — no clinical content — but it is where the day's takings live.

When it does not work

What you seeWhat it is
The address does not load on the phone at all Check the phone is on the clinic wifi and not mobile data, and not on a Guest network. Then try the router's own admin page from the phone: if that loads and the station does not, the router has client isolation switched on — look for "AP Isolation" or "Client Isolation" and turn it off.
It worked yesterday, today it does not The station's address changed. Read the current one from the station window, and do step 3 properly this time.
"This device cannot back itself up" You are on the http:// address. Install the certificate and use the https:// one — step 5.
Certificate warning on the https address The certificate is not installed or, on iPhone, not switched on in Certificate Trust Settings.
The queue is not updating between devices Check the doctor's device is paired — the Queue tab shows a pairing box if not. Press Sync now once. If the message says the address is a setup page, you are on http:// instead of https://.
The station lists several addresses Use the one it recommends first. The others are virtual adapters that exist only inside that PC and can never work from another device.

Honest limitations

  • The station binary is not code-signed. Windows will warn about an unknown publisher every time a new copy is run.
  • No tray icon, no auto-start, no updater. The window must stay open, and a new version means replacing the file.
  • The pairing code is not encryption. It stops a phone on the clinic wifi from reading the queue by guessing a URL. The TLS certificate is what protects the traffic itself.
  • The station must be running for the queue to sync. The doctor's app keeps working offline regardless, because the records are on that device.
